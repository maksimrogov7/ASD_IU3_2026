## Идеи решений и расчёт асимптотики

В таблице указана память метода `solve`, сверх входного массива.
Входной массив во всех программах занимает O(n).
Общий ввод и формирование текстового вывода требуют O(n) времени и до O(n) памяти.

| № | Идея | Расчёт времени | Время | Дополнительная память |
|---|---|---|---|---|
| 1 | Одновременно обновлять минимум и максимум | Один проход по n элементам | O(n) | O(1) |
| 2 | Искать слева направо, вернуть первое совпадение | Не более n сравнений | O(n) | O(1) |
| 3 | Увеличивать счётчик совпадений | n сравнений | O(n) | O(1) |
| 4 | Подсчитать совпадения, выделить массив индексов и заполнить | Два прохода: n + n | O(n) | O(m), m — число совпадений |
| 5 | Сложить элементы с индексами 0, 2, 4, … | Около n/2 сложений | O(n) | O(1) |
| 6 | Найти сумму и среднее, затем подсчитать превышения | Два прохода: n + n | O(n) | O(1) |
| 7 | Поддерживать два наибольших элемента | Инициализация и n − 2 итерации | O(n) | O(1) |
| 8 | Подсчитать знаки, затем заполнить два массива в исходном порядке | Два прохода: n + n | O(n) | O(p + q), p + q ≤ n |
| 9 | Проверить соседние пары, выйти при первом убывании | Не более n − 1 сравнений | O(n) | O(1) |
| 10 | Искать кратный элемент справа налево | Не более n проверок остатка | O(n) | O(1) |
| 11 | Найти сумму, сравнить точные масштабированные расстояния | Два прохода: n + n | O(n) | O(1) |
| 12 | Обходить справа налево, хранить ближайший справа индекс каждого значения в HashMap | n поисков и вставок | Ожидаемо O(n); при коллизиях до O(n log n) | O(n) |
| 25 | Накапливать сумму в long | n сложений | O(n) | O(1) |
| 26 | Нормализовать множитель и брать остаток после каждого умножения | n умножений и операций остатка | O(n) | O(1) |
| 27 | Вычислять каждый квадрат в long и складывать в BigInteger | n возведений в квадрат и сложений | O(n) при заданных ограничениях | O(1) при заданных ограничениях |

Стандартные массивы достаточны для всех задач, кроме №12: там таблица соответствия
«значение → минимальный индекс справа» позволяет избежать квадратичного перебора пар.
Используется стандартный `java.util.HashMap`, сторонних библиотек реализации алгоритмов нет.

### Корректность нетривиальных случаев

**Задача 7.** Первые два различных элемента задают максимум и второй максимум.
Каждый следующий элемент либо становится новым максимумом, сдвигая прежний на второе место,
либо обновляет только второй максимум. Поэтому после каждой итерации сохранены два наибольших
элемента просмотренной части. Значения `Integer.MIN_VALUE` обрабатываются без фиктивного маркера.

**Задача 11.** Вместо расстояния `|a[i] - sum/n|` сравнивается `|a[i]*n - sum|`.
Все расстояния умножены на одинаковое положительное n, поэтому порядок не меняется.
Вычисления выполняются в `long`, дробная арифметика не нужна.
Ответ обновляется только при строгом улучшении, сохраняя первый индекс при равенстве.

**Задача 12.** Перед обработкой i таблица содержит для каждого числа минимальный индекс j > i.
Сначала ищется дополнение, затем добавляется текущий элемент: использовать один элемент дважды нельзя.
При нахождении пары ответ обновляется; поскольку i уменьшается, итоговый i минимален.
Для этого i таблица уже содержит минимальный подходящий j.
Сумма и дополнение вычисляются в `long`, дополнение вне диапазона int не ищется в таблице.

Суммы элементов и масштабированные расстояния укладываются в `long` при n < 100000
и элементах типа int. Дополнительный параметр s в №12 читается как long, чтобы разрешить
сумму двух крайних int. В №6 используется гарантия условия о целом среднем, в №7 —
о различных элементах, в №10 — о ненулевом k.

**Задача 25.** Накопление суммы в long предотвращает переполнение int:
при допустимой длине модуль суммы меньше 100000 × 2^31.

**Задача 26.** Каждый элемент приводится к диапазону от 0 до MODULUS − 1 через
`Math.floorMod`. После каждого умножения берётся остаток.
Промежуточное произведение меньше (10^9 + 7)^2 и помещается в long.
Так корректно обрабатываются отрицательные числа, нули и крайние значения int.

**Задача 27.** Один квадрат int помещается в long, если преобразовать число до умножения.
Однако сумма квадратов может превышать long, поэтому накапливается в стандартном
`java.math.BigInteger`. При n < 100000 результат меньше 2^79, то есть размер
арифметических операций ограничен константой для диапазона задания.
В общем случае хранение ответа требует O(log(n × M²)) бит, где M — наибольший модуль элемента.

## Примеры ручных проверок

Во всех примерах перед массивом вводится его длина.

| № | Массив и дополнительный параметр | Ожидаемый ответ | Зачем проверять |
|---|---|---|---|
| 1 | `3 -8 0 12 3` | `-8 12` | Разные знаки и повторения |
| 2 | `4 7 4 9 4`, x = 4 | `0` | Нужно именно первое совпадение |
| 3 | `4 7 4 9 4`, x = 4 | `3` | Несколько вхождений |
| 4 | `4 7 4 9 4`, x = 4 | `0 2 4` | Порядок индексов |
| 5 | `2147483647 0 2147483647` | `4294967294` | Сумма выходит за int |
| 6 | `-4 -2` | `1` | Отрицательное среднее |
| 7 | `-2147483648 2147483647` | `-2147483648` | Минимальная длина и крайние int |
| 8 | `0 -2 3 -4 0 5 -6` | `3 5`, затем `-2 -4 -6` | Нули исключаются, порядок сохраняется |
| 9 | `-2 -2 0 8` | `YES` | Равные соседи допустимы |
| 10 | `7 0 8`, k = -3 | `1` | Ноль кратен отрицательному k |
| 11 | `7 1` | `7` | Равные расстояния: нужен первый |
| 12 | `1 2 3 4 5`, s = 6 | `0 4` | Минимальный i важнее меньшего j |
| 25 | `2147483647 2147483647` | `4294967294` | Сумма за пределами int |
| 26 | `-2 3` | `1000000001` | Неотрицательный остаток отрицательного произведения |
| 27 | `-2147483648 -2147483648` | `9223372036854775808` | Сумма квадратов за пределами long |

Также проверены пустой результат поиска, одинаковые элементы, отсутствие пары,
несколько подходящих j, дробное среднее, переводы строк и табуляция во входе.
